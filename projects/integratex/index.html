01 / CONTEXT

The friction.

Connecting CRM, email, payment, webhook and database systems repeatedly produces brittle integration logic and difficult-to-explain failures.

02 / PROPOSED SYSTEM

The response.

IntegrateX is being designed as a natural-language-to-workflow engine that translates intent into validated API steps with retries, idempotency and traceable execution.

06 / TECHNICAL DECISIONS

Why this shape?

DECISION / 01

Redis + Celery for durable work

Longer-running connectors need background execution, retries and observable task state.

DECISION / 02

Schemas as a safety boundary

The planner is constrained by connector contracts instead of inventing unsupported calls.

DECISION / 03

Idempotency by design

Retrying must not duplicate emails, payments or records when a downstream response is ambiguous.
